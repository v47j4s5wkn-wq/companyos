# DECISIONS.md — append-only
- D1 Stack = Supabase + React/Vite PWA + Dexie + Playwright — only option meeting RLS+realtime+solo-deploy+zero-cost simultaneously; escape hatch is plain Postgres.
- D2 Phase 1 gate = business shape (a) only; (b)(c) moved to Phase 2 — risky machinery is shape-independent; proving 3 shapes triples UI surface with no de-risking.
- D3 Staff email platform → Phase 5; Phase 1 ships outbound-only pipe (invites, proposals, chases) logged to timelines — mailbox client is a second product.
- D4 Phase 1 sends email from {tenant}.companyos.uk with tenant reply-to; custom domain = settings task, not onboarding — DNS propagation breaks the 5-minute Genesis bar.
- D5 Marketing mini-site + review engine → Phase 5; lead form + source attribution stay early; review gating needs a Google-policy-compliant redesign before build.
- D6 Buy not build: AISP for Open Banking, e-sign upgrade path, malware scanning, WhatsApp BSP.
- D7 GBP single currency through Phase 3; schema (minor units + currency code) keeps multi-currency additive.
- D8 Two-tier event payloads (full/redacted) written at the outbox, separate realtime channels per tier — a single stream cannot serve two permission tiers.
- D9 Op-log entities: payments, allocations, invoice issue/void, stock movements, work-status transitions, required checklist ticks, variation approvals. Everything else LWW + rev conflict diff.
- D10 Invoice numbering via per-tenant counter table, numbers assigned at issue (drafts unnumbered) — gapless under concurrency.
- D11 Custom field values in per-entity jsonb validated against custom_field_defs — first-class in forms/search/export without dynamic tables.
- D12 Backup: PITR + nightly logical backup offsite + tested restore runbook — added; brief omitted DR entirely.
- D13 AI metering per tenant with monthly cap from day one — live generator cost control.
- D14 Manifest schemaVersion added; validator ships before Genesis; state machines and event types are manifest data, not code.
- D15 Op ordering: ops carry client wall-time + entity rev; status collisions resolve via explicit reconciliation table; unlisted collisions become human conflict cards, never auto-resolved. (Reverses D9's implicit arrival-order.)
- D16 Invoice issue is online-only; offline prepares + queues, number assigned on apply, UI states it plainly. Gapless numbering and offline issuance are mutually exclusive — chose HMRC correctness.
- D17 contact_relationships many-to-many replaces single relationship column — a contact can be customer and supplier.
- D18 Deposits post to deferred-income liability; recognition event journals to income on completion/stage; revenue = recognised, cash = payments.
- D19 Outbox Relay is a named service doing tiered fan-out; postgres_changes never client-facing; relay p95 < 300ms budget.
- D20 Vocabulary = term service (singular/plural/article, templates, dual-term search indexing), built before any entity-naming screen.
- D21 Cut from P1 to P3: drive-time estimates, ICS import, days-to-paid analytics. ICS export stays in P1.
- D22 Zero-user run cost ~£35/mo accepted (PITR requires paid tier); AI usage capped per D13.
- D23 Unit/property test layer added: validator corpus, term service, VAT per scheme, allocation invariants, RRULE/DST, reconciliation table.
- D24 Design direction "British worksite instrument"; LIGHT theme default (dark UIs fail in sunlight — field-first product); dark = office preference only.
- D25 Type trio: Archivo (labelplates/display), Public Sans (body — Inter rejected as AI-tell), IBM Plex Mono (all figures, tabular). Platform accent = deep bronze-green #2E4A3A, replaced by tenant colour post-Genesis; hivis/signal/pass never tenant-overridable.
- D26 Signature element = the labelplate (tenant vocabulary stamped on every module header) + the christening (sole orchestrated animation, end of Genesis, reduced-motion honoured).
- D27 Site Mode: one-tap field mode — 17px floor, 64px targets, AAA-leaning contrast. Mobile-first as a mode, not a smear.
- D28 UUID v7 generated by a hand-rolled Postgres function, not a native/extension call — Supabase's managed Postgres version isn't guaranteed to ship native `uuidv7()` (added in PG18) or a v7-capable pgcrypto build yet; the hand-rolled version is portable and gets replaced by the native call once confirmed available.
- D29 `pgcrypto`/`citext` pinned to the `extensions` schema explicitly (`create extension ... with schema extensions`) and called schema-qualified (`extensions.gen_random_bytes`, `extensions.digest`, `extensions.citext`) from every SECURITY DEFINER function — Supabase installs these there, not `public`, and a SECURITY DEFINER function's `SET search_path` would otherwise silently fail to resolve them at runtime.
- D30 Invite delivery for Slice 1 is a manually-shared link (owner copies it from the UI), not automated email — no email provider (Postmark/SES-class per D3/D4) or DNS/domain exists yet at this point in the build. The invitations table/RPC design doesn't change when automated delivery is added later; only the "resend" action gains an actual send.
- D31 Invite acceptance for a brand-new email goes through a Supabase Edge Function calling `auth.admin.createUser()` (service role), not direct SQL inserts into `auth.users`/`auth.identities` — the latter is a known but unsupported hack that breaks silently across Supabase Auth schema migrations; the admin API is the stable, documented surface for creating a pre-confirmed user.
- D32 Local dev toolchain (Node 22, Supabase CLI, GitHub CLI) downloaded as standalone binaries rather than via Homebrew/system install — this build environment has neither Homebrew nor Docker, and this keeps setup local, reversible, and out of the repo.
- D33 Toolchain lives at `~/Desktop/companyos-toolchain/`, **outside** the repo directory, not in `.toolchain/` inside it (reverses D32's location) — deploy tooling zips the working directory and does not reliably respect `.gitignore`, so 366MB of Node binaries inside the repo broke uploads. Anything large and machine-local belongs outside the tree entirely.
- D34 Staging hosting = Netlify building from the GitHub repo on push, not machine-local uploads — the upload-and-build path failed repeatedly (400 on large payloads, then persistent 404), and git-based CD is the correct end state anyway per TURN1-SPEC §1's "CI deploys to staging on merge". Requires a one-time browser link of repo→project; after that no deploy depends on this machine.
- D35 No local Supabase stack (no Docker in this environment) — migrations are validated by parsing against real Postgres grammar (`pglast`/libpg_query) before being applied straight to hosted staging. Acceptable while staging holds no real data; revisit if a migration ever needs rehearsing before staging.
- D36 Staging auth: email confirmations OFF, temporarily — no transactional email provider exists yet (D3/D4 place it later) and Supabase's built-in sender is rate-limited demo plumbing, so confirmations can't be delivered reliably. MUST return to ON before prod takes real users: with it off, an unverified signup can squat any address, which demotes accept_invitation's email-match check to a second factor behind the token. Tracked in supabase/config.toml with the same warning inline.
- D37 accept_invitation() is the single owner of acceptance, and it is idempotent for re-acceptance by the same person — the Edge Function only verifies the invite and creates the confirmed auth user. Found by driving the deployed flow: the function duplicating membership-creation caused the client's follow-up RPC to fail on an already-used invite. One owner per state transition, everywhere, from now on.
- D38 Product name is OPEN — founder call. "Company OS"/`companyos` stays as the dev name underneath regardless (founder-stated). Shortlisted for consideration: Daybook (site diary + book of first entry; fits the labelplate register), Gaffer, Setsquare. Rename touches only the front-door plate, index.html title, PWA manifest, and D4's sending domain — deliberately cheap because the platform brand is quiet by design (tenants' names carry the UI). Verify domains + UK IPO classes 9/42 before committing.
